01 / Ubuntu audio repair · Legion Pro 7i Gen 10

Bring back
the bass.

Thin, unusually quiet sound on the Legion Pro 7i Gen 10 can mean the tweeters are playing while the woofers remain inactive. This guide explains the AW88399 amplifier path, checks compatibility, and walks through a repeatable Ubuntu repair.

Recognize the symptomThin. Quiet. No weight.

A tweeter-only output can be audible yet lack body and normal loudness.

Check the causeA missing woofer path

The ASoC chip driver alone does not provide the HDA integration required by these amplifiers.

Apply the matching fixDriver + firmware

Upstream Linux 7.3 includes the integration for the supported Intel codec IDs. Firmware must also be available. [1]

Start with compatibility checks. This page does not inspect or change the computer displaying it. The tested configuration is one reference case, not a claim about a reader’s laptop. Run --diagnose before choosing an installation path.

All 2D/3D models, waveforms and frequency plots are explanatory simulations. They are not acoustic measurements, real-time hardware readings or proof that an installation has succeeded.

02 / Hardware checks & tested configuration

Match the hardware.
Then choose the fix.

This installer targets the Intel Legion Pro 7 16IAX10H audio design. Similar Legion model names can use different amplifiers; verify the model, codec subsystem ID and ACPI device instead of applying a generic speaker workaround.

Model guard
16IAX10H · 83F5

The script checks Lenovo DMI identity, the 16IAX10H model string and x86_64 architecture. Other Legion generations and AMD models are outside this installer’s scope.

Codec guard
ALC287 · 3906 / 3907

Accepted codec subsystem IDs: 17aa:3906 and 17aa:3907. End-to-end testing covered 3906; the second accepted ID has not been independently tested with this wrapper.

Amplifier guard
AWDZ8399 → AW88399

The ACPI device must identify the Awinic AW88399 amplifier pair. Cirrus and TAS2781 firmware fixes are for different hardware.

Operating-system scope
Ubuntu · x86_64

The script permits Ubuntu 22.04 or newer. Only Ubuntu 24.04.5 was tested end to end. The custom-kernel path requires GRUB; derivatives and other releases are not certified.

Collect a read-only diagnosis

bash legion-speaker-fix.sh --diagnose

The command reports the running kernel, codec ID, firmware paths, driver availability and amplifier bindings. It does not install packages, play sound or change mixer settings.

Example of an affected boot log

ALC287: picked fixup  for PCI SSID 17aa:0000

A generic fixup together with missing HDA amplifier support and firmware is consistent with this fault. The log line alone is not enough to diagnose every quiet-speaker problem.

Tested configuration · 6 Nov 2026

One documented reference case

Hardware: 83F5 / 16IAX10H, codec 17aa:3906.
OS: Ubuntu 24.04.5 LTS.
Before: kernel 7.0.0-42-generic, missing HDA bridge and firmware.
After: 7.3.1-legion-aw88399, Secure Boot enabled, two HDA amplifier bindings.

Reported outcome: bass and normal loudness restored. NVIDIA 595.99.02 also responded normally. This is a subjective listening report on one configuration, not a benchmark or a guarantee for every laptop.

No acoustic measurements or confirmed headphone, microphone or suspend/resume results are available.

Four speakers can still use stereo. Two audio channels can feed both tweeters and woofers. A “4.0 surround” profile does not substitute for the amplifier driver and firmware.

Why “ALC3306” and “ALC287” can coexist

Lenovo’s specification uses the ALC3306 name; Linux identifies the codec in the tested configuration as ALC287. Match the codec subsystem ID and amplifier hardware when selecting a repair. [4]

04 / Installation paths & prerequisites

One kit.
Two repair paths.

The installer checks the running kernel for the actual HDA side codec. It keeps a kernel that already provides support, or builds the pinned upstream reference kernel when support is missing on an older kernel.

Choose by diagnosis, not by this example. The reference installation succeeded on Ubuntu 24.04.5. Other systems may already have native support, need different prerequisites, or be outside the hardware guard. A stopped installer is not a reason to bypass its checks.

Download the public installer

Save the script using the button or obtain it from the repository. The HTML contains the script; vendor firmware is downloaded separately from a commit-pinned upstream URL and checked against a pinned SHA-256.

Diagnose before installing

Open a terminal in the script’s folder. Confirm the model and codec ID. Before installation or testing, lower built-in speaker volume to 15–20%.

bash legion-speaker-fix.sh --diagnose
bash legion-speaker-fix.sh --install

Follow the applicable path

HDA side codec present: install missing firmware and refresh the current boot image.
Older kernel without support: build and package Linux 7.3.1 locally, retaining the existing kernel.

The build path needs AC power, internet, at least 35 GiB free in the account cache and 450 MiB in /boot. It may take an hour or more. A rerun reuses completed kernel packages.

Enroll, trial and verify

The script never reboots automatically. If a signing key needs enrollment, reboot to enroll it first. Back in Ubuntu, run --boot-repair to verify trust and schedule one trial boot, then reboot again. The existing kernel remains the default until --commit.

What can change?

Missing firmware under /lib/firmware. On the build path: local kernel packages, a local signing key, a GRUB selection file, matching NVIDIA DKMS support and a coexistence rule in /etc/dkms/nvidia.conf.

Logs and backups are kept in /var/lib/legion-speaker-fix. Existing firmware is retained. Conflicting audio overrides or an older AW88399 DKMS installation stop the script for review.

Interpret a diagnosis

Paste output from --diagnose. This helper reads pasted text locally and does not upload it or inspect hardware.

The inspected Ubuntu mainline 7.3.1 header package required libssl4, unavailable in Noble. The reference route builds with the installed system’s libraries. This is not a recommendation to mix base libraries from different Ubuntu releases.

05 / Secure Boot & the first trial

A new driver.
A complete chain of trust.

A locally built kernel needs a trusted boot-image signature when Secure Boot is enabled. The installer creates a local boot-signing key and requests enrollment of its public certificate. Kernel-module keys and boot-image keys are not interchangeable in every configuration. [3]

If enrollment is required

Queue the public certificate

bash legion-speaker-fix.sh --boot-repair

Create a temporary enrollment password locally. Wait for confirmation that the certificate is queued before rebooting. This command reuses the existing kernel and key; it does not rebuild.

Complete MOK Manager enrollment

At reboot, press a key when prompted. Select Enroll MOK → Continue → Yes, enter the temporary password and complete the requested reboot. The existing Ubuntu kernel boots first.

Schedule the trusted trial

Run --boot-repair again. It checks the exact certificate fingerprint in the enrolled-key list. Reboot when it reports READY FOR ONE TRIAL BOOT. On the custom route, uname -r should then show 7.3.1-legion-aw88399.

Recovery stays available

Keep the previous kernel.

The installer exposes GRUB’s menu for ten seconds. If the trial fails, choose Advanced options for Ubuntu and select the kernel that worked before installation. Its version is specific to each system.

Active graphics, storage and networking drivers are checked for candidate availability. Matching NVIDIA DKMS support is prepared when needed. Availability checks do not replace real boot, display and peripheral testing.

Do not infer trust from a successful signing command. The public certificate must also be enrolled. The installer compares certificate fingerprints rather than relying on mokutil --test-key exit status.
Native-support path: a distribution kernel that already provides the required HDA driver stays in use. If only firmware was needed, the custom-kernel signing and trial sequence does not apply.
06 / Verify, keep or roll back

Make the result
prove itself.

After the trial boot, choose the built-in speakers and start at 15–20% volume. Check the driver state first, then test audible output and the devices used day to day.

bash legion-speaker-fix.sh --verify

Expected software result: HDA woofer driver available and HDA amplifier bindings: 2 / 2. A binding check alone cannot establish sound quality or physical speaker output.

0 of 5 checks marked. This checklist is a local test record, not an automatic test.
After a successful custom-kernel trial

Keep the working kernel

bash legion-speaker-fix.sh --commit

This selects the tested custom kernel as the normal default. The previous kernel remains available in GRUB.

Plan for kernel maintenance. The pinned custom kernel does not receive automatic Ubuntu kernel security updates. Keep Ubuntu updates enabled and move to a supported Ubuntu kernel with native AW88399 support when available.
If a regression appears

Restore the previous boot

bash legion-speaker-fix.sh --rollback

Then reboot. If the desktop is unavailable, select the previous kernel in GRUB’s Advanced options first.

Rollback changes the boot selection and cancels the trial. Firmware, packages, certificates, the NVIDIA coexistence rule and logs remain available. It is not a full uninstall.

SymptomNext check
Firmware load errorRun --diagnose. The installer supplies the legacy and SSID-specific firmware layouts documented upstream, without replacing existing files. Check source availability and the printed integrity result.
“bad shim signature”Boot the previous Ubuntu kernel and run --boot-repair. Complete enrollment, then rerun the command to schedule the trusted trial.
NVIDIA version collisionThe coexistence rule keeps an identical Ubuntu-packaged driver on stock kernels. Rerun --install to recover an interrupted package state and reuse completed kernel packages. Do not force an overwrite.
Kernel or driver build failsThe installer stops. Use the dated log under /var/lib/legion-speaker-fix while continuing to boot the previous kernel.
2/2 bindings, still no bassCheck speaker routing, mixer state and logs during playback. Binding alone does not exclude a remaining driver, firmware or hardware problem.
07 / Sources, test scope & reuse

Understand the fix.
Keep it reproducible.

This public guide contains its own graphics, animations, JavaScript, installer download and anonymized tested configuration. The guide opens offline. Installation downloads vendor firmware and, when needed, kernel source and build packages.

Reuse after an Ubuntu reinstall

Open the HTML locally, download the script, inspect --diagnose output and follow the matching installation path. Firmware and kernel downloads are pinned and hash checked. Unknown hardware is rejected; a newer kernel that omitted the driver is not silently downgraded.

The custom source version is pinned to 7.3.1, not a live update feed. Check the linked upstream project and Ubuntu’s supported kernels before choosing a long-term kernel. Only the reference configuration described in Chapter 2 was validated end to end.
